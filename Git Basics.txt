Initialize and snapshot work.

git init
printf "Hello\n" > README.md
git add README.md
git commit -m "Add README"

After creating one commit, explore status and history.
git status
git log --oneline --graph --decorate --all

Stage precisely with patch mode, then commit meaningful messages.
echo "tip" >> README.md
git add -p README.md
git commit -m "Add quick tip to README"

Create a remote, fetch, and push safely.

git remote add origin https://github.com/user/repo.git
git fetch origin
git branch --set-upstream-to=origin/main main
git push -u origin main

Recover from mistakes without losing work by using the stash and restore.
echo "WIP" >> app.js
git stash push -m "wip app"
git pull --rebase
git stash pop


Between snippets remember: the index is authoritative for the next commit. Stage only what you intend to record.



what does of this commands do? echo "WIP" >> app.js git stash push -m "wip app" git pull --rebase git stash pop

echo "WIP" >> app.js

Adds the text "WIP" to the end of app.js
This simulates you making changes to a file (work in progress)
git stash push -m "wip app"

Stashes your uncommitted changes (both staged and unstaged)
The -m "wip app" adds a message so you can identify this stash later
Your working tree becomes clean — changes are safely stored away
Use case: You're mid-feature but need to switch branches urgently (e.g., fix a bug)

git pull --rebase

Fetches the latest changes from the remote
Rebases your local commits on top of the remote branch (instead of merging)
This keeps history linear and cleaner than a merge commit
Why rebase here? You stashed your work, so there's nothing to conflict with
git stash pop

Retrieves your stashed changes and applies them back to your working tree
Removes the stash after applying (unlike git stash apply, which keeps it)
Your WIP is restored, ready to continue

Gitignore
Create common patterns and verify what Git sees.
echo "node_modules/" >> .gitignore
echo "*.log" >> .gitignore
echo "!.env.example" >> .gitignore
printf "PORT=8080\n" > .env

List untracked files after rules are in place.
git status --ignored

Use directory-scoped .gitignore for generated docs.

mkdir -p docs/build
echo "build/" > docs/.gitignore

Configure a global ignore file for OS artifacts.

git config --global core.excludesfile ~/.gitignore_global
echo ".DS_Store" >> ~/.gitignore_global
echo "Thumbs.db"   >> ~/.gitignore_global

Stop tracking a file that slipped into history while keeping it locally.
git rm --cached path/to/file && echo "path/to/file" >> .gitignore
